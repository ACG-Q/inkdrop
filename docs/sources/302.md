# 302 源开发文档

## 概述

302 源通过 HTTP 302 重定向获取壁纸 URL，适用于提供随机壁纸的 API。每次请求会返回一个重定向响应，指向实际的图片 URL。

## 工作原理

1. 向指定 URL 发送 HTTP 请求
2. 服务器返回 302 重定向响应
3. 从响应头中获取 `Location` 字段（即实际图片 URL）
4. 重复请求多次以获取多张壁纸

## 配置格式

```json
{
  "sourceId": "random_image",
  "sourceName": "随机图片",
  "url": "https://api.example.com/random",
  "imageUrlBase": "",
  "categories": []
}
```

## 字段说明

### 必填字段

| 字段 | 类型 | 说明 |
|------|------|------|
| `sourceId` | string | 源的唯一标识符 |
| `url` | string | 302 重定向 API 地址 |

### 可选字段

| 字段 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `sourceName` | string | sourceId | 源的显示名称 |
| `imageUrlBase` | string | "" | 图片 URL 基础路径（通常为空） |

## URL 模板变量

| 变量 | 说明 |
|------|------|
| `{page}` | 当前页码 |
| `{pageSize}` | 每页数量 |
| `{timestamp}` | 当前时间戳 |

## 请求流程

```
客户端 → GET /random → 服务器
                          ↓
                    302 Found
                    Location: /images/abc123.jpg
                          ↓
客户端 ← 重定向响应 ← 服务器
        ↓
获取 Location 字段值
        ↓
实际图片 URL: /images/abc123.jpg
```

## 完整示例

### 示例 1：简单随机图片

```json
{
  "sourceId": "random_cat",
  "sourceName": "随机猫咪",
  "url": "https://cataas.com/cat",
  "imageUrlBase": ""
}
```

工作流程：
1. 请求 `https://cataas.com/cat`
2. 服务器返回 302 重定向到 `https://cataas.com/cat/abc123`
3. 获取实际图片 URL

### 示例 2：带参数的随机图片

```json
{
  "sourceId": "random_dog",
  "sourceName": "随机狗狗",
  "url": "https://dog.ceo/api/breeds/image/random/{pageSize}",
  "imageUrlBase": ""
}
```

工作流程：
1. 请求 `https://dog.ceo/api/breeds/image/random/5`
2. 返回 JSON 响应（非 302）
3. 解析 JSON 获取图片 URL

### 示例 3：随机风景

```json
{
  "sourceId": "random_landscape",
  "sourceName": "随机风景",
  "url": "https://source.unsplash.com/random/1920x1080?nature",
  "imageUrlBase": ""
}
```

工作流程：
1. 请求 `https://source.unsplash.com/random/1920x1080?nature`
2. Unsplash 返回 302 重定向到实际图片
3. 获取最终图片 URL

## 响应处理

### 302 重定向响应

```
HTTP/1.1 302 Found
Location: /images/wallpaper.jpg
```

### 直接返回 URL 的 API

某些 API 可能直接返回 JSON：

```json
{
  "url": "https://example.com/image.jpg",
  "width": 1920,
  "height": 1080
}
```

## 与其他源类型的区别

| 特性 | 302 源 | JSON 源 | JS 源 |
|------|--------|---------|-------|
| 数据格式 | 重定向 URL | JSON 列表 | 自定义逻辑 |
| 分页支持 | 不支持 | 支持 | 支持 |
| 分类支持 | 不支持 | 支持 | 支持 |
| 灵活性 | 低 | 中 | 高 |
| 适用场景 | 随机壁纸 | 标准 API | 复杂逻辑 |

## 注意事项

1. **不支持分页**：302 源每次请求返回固定数量的壁纸
2. **不支持分类**：无法按分类筛选壁纸
3. **网络请求**：每次加载壁纸都会发起网络请求
4. **超时设置**：默认 15 秒连接超时，15 秒读取超时
5. **重定向限制**：不会自动跟随重定向，需要手动处理

## 最佳实践

1. 选择可靠的 302 重定向 API
2. 确保 API 响应时间稳定
3. 考虑使用缓存减少重复请求
4. 处理网络异常情况

## 常见问题

### Q: 为什么只显示一张壁纸？
A: 302 源需要多次请求才能获取多张壁纸，检查 API 是否正常工作。

### Q: 壁纸加载很慢？
A: 检查网络连接和 API 响应时间，考虑使用更快的 API。

### Q: 如何测试 302 源？
A: 使用 curl 命令测试：
```bash
curl -v https://api.example.com/random
```
查看响应头中的 `Location` 字段。
